## Summary

staff must accept the current version of the employment terms before accessing any content.
Backed this with an `onStaffUpdatedTrigger` Cloud Function that creates immutable audit log
records on any compliance-sensitive field change. Added CSV and JSON export capabilities to
the Admin panel for payroll and compliance purposes.

## Compliance Alignment (PIPEDA / Law 25)

- Terms history stored in staff document under `compliance.termsHistory[]` — never in a public collection.
- Audit log entries are admin-readable only (Firestore rules restrict reads to `admin` role).
- No PII is written to Cloud Function logs; only field-name change diffs and timestamps.
- IP address captured at consent time is stored in the staff document (not the log) for traceability.
- Export files are generated client-side (never stored server-side) — user downloads only.

## Known Limitations

- \`TermsConsentOverlay\` fetches public IP via \`https://api.ipify.org\` — if the network is
  unavailable, the IP field gracefully falls back to \`'unknown'\` and consent proceeds normally.
- Export modal performs client-side data assembly; for very large staff datasets (>500 jobs)
  a server-side export endpoint (Cloud Function) should be considered in a future epic.
