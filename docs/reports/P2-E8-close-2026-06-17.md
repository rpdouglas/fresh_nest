# Epic Close Report: P2-E8 Firebase Custom Claims RBAC
**Completion Date:** 2026-06-17

---

## 1. Objective Achieved
We successfully migrated the Fresh Nest Co. applications and Firebase database backend from the old Firestore collection email allowlist pattern to cryptographically secure Firebase Custom Claims for Role-Based Access Control (RBAC). 

This migration completely eliminates database document reads in Firestore security rules for role checking, reducing operational costs and latency.

---

## 2. Key Tasks Completed

### Backend & Cloud Functions
- **Dynamic On-Signup Assignment (`onUserCreated`):** Modified the Auth trigger to automatically match signing-up user emails with the `admins` collection (sets `role: 'admin'`) and the `staff` registry (sets `role: 'staff'` or `'supervisor'` based on their FSM registry role). Unrecognized user signups default to `role: 'customer'`.
- **Admin Role Administration (`setUserRole`):** Created a secure HTTPS callable function that allows administrators to change user roles.
- **Admin Bootstrapping:** Programmed a fallback check in `setUserRole` and `getAnalyticsKPIs` that allows users present in the legacy Firestore `admins` collection to invoke functions until their token claims are set.

### Database Security Rules
- **Access Control Refactor (`firestore.rules` & `firestore.dev.rules`):** Redefined `isAdmin()` to check token custom claims (`request.auth.token.role == 'admin'`) rather than making a Firestore look-up.
- **Staff-Only Rules (`isStaff()`):** Added a helper function to secure `/checklistTemplates` and `/jobs` collections, verifying that only `'staff'`, `'supervisor'`, or `'admin'` claim holders can read/write.

### Client Applications
- **Customer App Admin Dashboard:** Re-implemented `useAdminAuth` hook to query `idTokenResult.claims.role === 'admin'`, removing the Firestore look-up code.
- **FSM App Routing Guard:** Modified `ProtectedRoute` and `StaffAuthProvider` to verify the custom claim role is `'staff'`, `'supervisor'`, or `'admin'`, blocking customer accounts and ensuring only verified cleaners and supervisors get access to scheduling resources.
