## Work Done

1. **`StaffDetailPanel.tsx`** (new): expandable admin panel modeled directly on the existing `BookingDetailPanel.tsx` (`AnimatePresence` row expansion, same card/section layout, same brand tokens). Sections:
   - **Onboarding Checklist**: employment agreement (read-only, from C1), background check consent (read-only, from B2), the **relocated** background-check status editor (moved from `StaffTable.tsx`, unchanged logic), WHMIS/platform training completion (read-only, from C3), and the four genuinely new admin-only toggles — ID Verified, Supervised Shift Completed, Uniform Issued, Direct Deposit on File.

   - **Status Management**: "Activate Employee" button, gated on background check cleared + ID verified + employment agreement signed + platform training complete.

2. **`StaffTable.tsx`**: rewritten to add row-click-to-expand (`expandedRowId` state, mirroring `BookingsTable.tsx`'s `isExpanded` pattern exactly); removed the B2-era inline background-check editor and the separate Actions column, both consolidated into the new panel — Lauren now has one place for onboarding actions instead of two.
3. **`useStaff.ts`**: added `updateChecklistItem` (direct `updateDoc` to `onboardingChecklist.{item}`, `item` typed as a closed 4-member union — no arbitrary field-path injection possible) and `activateEmployee` (direct `updateDoc` of `status: 'active'`). 4. **`onStaffUpdatedTrigger`**: extended to diff the four new admin-only fields for `auditLog`, matching the existing pattern already used for `status`/`role`/`financials.monthlyEarningsLimit`.
5. **Schema**: documented the four new fields in `docs/firestore-schema.md`.
