## Technical Notes

### Zod v4 + `@hookform/resolvers` v5 Resolver Type Fix
Schemas using `.default()` or `z.preprocess()` produce input/output type divergence that breaks `Resolver<BookingFormData>`. Fixed by:
1. Removing all `.default()` calls from schema; rely on `defaultValues` in `useForm` instead.
2. Replacing `z.preprocess()` on `squareFootage` with plain `.optional()`; handle empty string → `undefined` via `setValueAs` in `register()`.
3. Applying `as Resolver<BookingFormData>` cast to `zodResolver()`.

### URL Pre-population
`buildDefaults()` maps QuoteCalculator URL params to schema values:
- `size=5plus` → `propertyType='5+bed'`
- `service=airbnb` / `serviceType=airbnb` → `serviceType='airbnb'`
- `commercial=1` → both `serviceType` and `propertyType` set to `'commercial'`
