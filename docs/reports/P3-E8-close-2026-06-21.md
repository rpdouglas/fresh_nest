## Query Change Detail

**Before:** `queryKey: ['bookings', startDate, endDate]` — filter dropdowns applied as `useMemo` over the loaded page only.

**After:** `queryKey: ['bookings', startDate, endDate, statusFilter, serviceFilter, languageFilter]` — any filter change triggers a fresh Firestore fetch with server-side `where()` clauses.

```typescript
if (statusFilter !== 'all')   q = query(q, where('status', '==', statusFilter))
if (serviceFilter !== 'all')  q = query(q, where('serviceType', '==', serviceFilter))
if (languageFilter !== 'all') q = query(q, where('language', '==', languageFilter))
```

Sort (`sortBy`, `sortOrder`) remains client-side — cursor-based pagination (`startAfter`) depends on the Firestore `orderBy` field (`preferredDate`). Free-text search remains client-side (Firestore does not support full-text search).

## Indexes Declared (7 new)

| Index | Fields |
| :--- | :--- |
| Single: status | `status ASC · preferredDate DESC` |
| Single: serviceType | `serviceType ASC · preferredDate DESC` |
| Single: language | `language ASC · preferredDate DESC` |
| Double: status + serviceType | `status ASC · serviceType ASC · preferredDate DESC` |
| Double: status + language | `status ASC · language ASC · preferredDate DESC` |
| Double: serviceType + language | `serviceType ASC · language ASC · preferredDate DESC` |
| Triple: all three | `status ASC · serviceType ASC · language ASC · preferredDate DESC` |

**Deploy order:** `firebase deploy --only firestore:indexes` must be run and indexes must finish building before the code is deployed. Deploying code before indexes are ready will throw missing-index errors.
