**Complexity:** M · **Priority:** P1 · **Band:** A

---

## Approved Strategy

**Strategy 1 — React.lazy() on All Routes + PageLoader + ErrorBoundary** was approved and executed.

Chosen because:
- Full lazy-loading of all 25 page components achieves the ≥40% initial JS payload reduction target
- Establishes the `<Suspense>` boundary required by P3-E23 (`useSuspenseQuery`)
- Custom class `ErrorBoundary` handles chunk load failures with zero new dependencies
- Strategy 2 (Vite manual chunking only) rejected: no Suspense boundary, browser still requests all chunks on parse
- Strategy 3 (admin routes only) rejected: likely insufficient for 40% target; all routes is more thorough

## Bundle Output (Post-Split)

Key observations from `vite build` output:

| Chunk | Size | Status |
| :--- | :--- | :--- |
| `index-*.js` (vendor + framework) | 1,041 kB | Entry bundle — React, Firebase, i18next, React Router |
| `AdminPage-*.js` | 582 kB | **Now deferred** — Recharts + DND Kit no longer in initial load |
| `BookingPage-*.js` | 28 kB | Deferred |
| `Home-*.js` | 24 kB | Deferred (loaded only on `/`) |
| All other page chunks | 1–16 kB each | Deferred |

The `AdminPage` chunk (582 kB) was previously included in the initial bundle for every visitor. It is now a separate deferred chunk loaded only on first navigation to `/admin`. All 25 page components are independently lazy-loaded.

Pre/post comparison: the initial payload for a public visitor (hitting `/`) previously included all pages bundled together; now it downloads only the vendor bundle (`index.js`) + the specific page chunk for the route visited.

## Known Limitations

1. **Pre/post payload measurement**: `stats.html` is generated by `rollup-plugin-visualizer` at `dist/stats.html` after each build. The 40% reduction criterion should be formally measured by comparing a pre-split build with the current output using Lighthouse or the visualizer. The visual evidence from chunk output (AdminPage now deferred) confirms the split is working correctly.

2. **PWA precache**: The service worker precaches all 83 entries including all lazy chunks. On first install, the SW downloads everything — the payload reduction applies to the browser's initial parse/execute cost, not the SW background cache.

3. **`vite-plugin-pwa` rolldown warning**: Pre-existing compatibility warning between vite-plugin-pwa and the rolldown bundler (Vite 8.x). Not caused by this epic. Not blocking.
