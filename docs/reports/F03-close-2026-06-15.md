## Summary

F03 implements the automated booking-to-job conversion pipeline. When an admin confirms a booking in the Customer App admin panel, a Cloud Function (`onBookingStatusConfirmed`) atomically creates a Job document in `/jobs` and writes the `jobId` back to the booking. A new **Checklist Template Manager** tab in the admin panel allows admins to create, edit, reorder, and deactivate service-specific task lists with full EN/FR labels, icon selection, `requiresPhoto`, and `photoPhase` fields.

## Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Trigger strategy | `onDocumentUpdated` on `bookings/{docId}` | Fires on every field update; status guard prevents unwanted runs |
| Duplicate guard | Query `/jobs` for existing `bookingId` before creating | Prevents re-fires if admin re-saves confirmed status |
| Pay rate resolution | Query `payRates` for active cleaner role; graceful null fallback | No crash if `payRates` collection doesn't exist yet |
| Template resolution | Match by `serviceType` → fallback to first active template | Always creates a job, even if no exact template match |
| Atomicity | `db.runTransaction()` — create job + write `jobId` to booking | Guarantees both writes succeed or both fail |
| Hook pattern | `useCollectionQuery` (TanStack Query) | Matches `useBookings`/`useStaff` pattern; eliminates `setState`-in-effect lint violations |
| Drag-and-drop | `@dnd-kit/core` + `@dnd-kit/sortable` | Lightweight, accessible, well-maintained |
