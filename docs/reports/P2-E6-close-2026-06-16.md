## Architecture Decisions

- **Projection Query Optimization:** Inside the Cloud Function `getAnalyticsKPIs`, instead of downloading full booking document payloads to perform grouping and historical fallback calculations, we use a projection query (`select()`) to fetch only essential properties. This reduces bandwidth, function CPU execution time, and memory overhead.
- **Dynamic Pricing Fallback:** To maintain backward-compatibility with historical bookings that lack the new `estimatedPrice` field, the Cloud Function runs an in-memory pricing calculation fallback utilizing identical pricing factors (multipliers and frequency discounts) as the client-side calculator.
- **Compound Queries Avoidance:** Bookings and jobs collections queries are limited and sorted by the same date field (`preferredDate` / `scheduledDate`). This enables range filtering and descending sorting in Firestore without requiring the deployment of custom composite indexes.
