## What shipped

### PR 1 (#52): server side and rules
- **Comparison module** (`packages/shared/src/domain/audit.ts`, synced into `functions/`):
  - one entry per save, with `actor`, `source`, `action`, and `changes: [{ field, before, after }]` for the watched fields (`AUDIT_CONFIG`);
  - a snapshot on delete;
  - capped values.
- **Seven `onDocumentWritten` audit triggers:** bookings, jobs, staff, checklistTemplates, payRates, galleryPairs, reviews.
- **`lastChange` stamp** on every app and server save.
  - The trigger credits a person only when the save set a new stamp.
  - Server code stamps `system:<function>`; `claimJob` names the cleaner.
  - Dispatch overrides carry their reason and type on the stamp.
- **Rules:**
  - `auditLog` is read-only for the office; no app can write it.
  - A stamp must name the signed-in email at the request time.
  - Tolerant period: the stamp may be absent or left unchanged.
- **Other:**
  - a history index;
  - `onStaffUpdatedTrigger` kept as a no-op (F17);
  - schema documentation.

### PR 2: screens
- **`RecordHistory`:**
  - collapsible, and it loads only when opened;
  - it merges several records, such as a booking and its visit;
  - shown in the **booking panel**.
- **`HistoryDialog`:** opened from the 🕘 button on **Dispatch cards** and the **History** button in the **Staff Registry**.
- **`AuditEntryView`:**
  - shows who, when and from which app, then each field crossed-out old → new;
  - shows the reason and override type, and the deleted record's snapshot;
  - reads both entry shapes (P3-E37 and the older one-field rows).
- **Audit Logs tab:** rebuilt as a list that works on phones, with:
  - search across person, client, record ID, reason and field;
  - filters for record type, person, app, override type and a date range;
  - a **Clear filters** button and an entry count.
- **EN/FR strings:** about 60 field labels, plus source, action and actor wording.
- **Admin guide:** a new "Audit Log and History" section.
