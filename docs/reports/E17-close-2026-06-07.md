# E17 Close Report — Cloud Functions Bilingual Email
**Date:** 2026-06-07
**Strategy executed:** Strategy 1 — Firebase Functions v2 + Resend SDK

---

## Summary

Implemented a Cloud Functions v2 Firestore trigger (`onBookingCreated`) that fires on every new document in the `bookings` collection (production DB only). On each new booking:
1. Sends an owner notification (plain-text, always EN) with all 19 booking fields + Booking ID
2. Sends a client confirmation (branded HTML email, EN or FR based on `booking.language`)

Both sends are attempted with `Promise.allSettled` — one failure never blocks the other and never causes Cloud Functions to retry (which would duplicate emails).

## Architecture Decisions

- **Trigger scope `database: '(default)'`** — dev DB writes (`freshnest-dev`) do not send emails
- **`defineSecret` for `RESEND_API_KEY` and `OWNER_EMAIL`** — stored in Firebase Secret Manager; never in source
- **`FROM_EMAIL` via `process.env`** — non-sensitive sender address; hardcoded fallback `Fresh Nest Co. <noreply@freshnestco.ca>`
- **`Promise.allSettled`** — both email attempts made; failures logged (not rethrown), preventing retry-induced duplicates
- **`esc()` helper** — all user-provided content HTML-escaped before insertion into email template

## Pre-Deployment Steps (Human Required)

Before deploying functions, the owner must:

```bash
# 1. Create Resend account at resend.com, add domain freshnestco.ca, get API key
firebase functions:secrets:set RESEND_API_KEY

# 2. Set the owner notification recipient email
firebase functions:secrets:set OWNER_EMAIL

# 3. Deploy functions
firebase deploy --only functions
```

`FROM_EMAIL` is optional — defaults to `Fresh Nest Co. <noreply@freshnestco.ca>`. To override:
```bash
# Set as environment variable in firebase.json or via Firebase Console
```
