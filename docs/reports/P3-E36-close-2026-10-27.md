## 1. Summary of Changes

Implemented the company-wide **Operational Settings & Policy Record with Versioned History** (`settings/policy` and `settings/policy/history/{version}`), the Owner-only `updatePolicySettings` callable Cloud Function, the Admin **Settings & Policies** tab (editable by Owners, read-only for Managers), and live runtime wiring across scheduling travel buffers and ODSP earnings thresholds so changing a setting alters platform behaviour immediately without a code deployment.

### Key Deliverables
1. **Shared Domain Schema & Validation (`packages/shared/src/domain/policy.ts`, synced to `functions/src/shared/policy.ts`):**
   - Defined `PolicySettingsValues`, `PolicySettings`, `PolicyFieldDiff`, `PolicyHistoryEntry`, `DEFAULT_POLICY_SETTINGS`, `POLICY_NUMERIC_BOUNDS`, `normalizePolicySettings`, `validatePolicySettingsInput`, and `computePolicyDiff`.
   - Added typed Firestore converters `policySettingsConverter`, `policyHistoryConverter`, `policySettingsDoc`, and `policyHistoryCollection` in `packages/shared/src/firebase/converters.ts`.
2. **Owner-Only Server Write Path & Version History (`functions/src/callable/settings.ts`):**
   - Created `preparePolicyUpdate` (pure helper) and `updatePolicySettings` callable Cloud Function.
   - Verifies caller is an **Owner** (`resolveOfficeRole(caller, db) === 'owner'`), validates bounds, increments `version` (`1, 2, 3…`), writes `settings/policy`, appends an immutable snapshot + field-by-field diff to `settings/policy/history/{version}`, and writes an `auditLog` entry (`overrideType: 'policy_change'`).
3. **Firestore Security Rules (`firestore.rules`, `firestore.dev.rules`, `apps/customer/test/firestore-rules.test.ts`):**
   - `settings/policy`: `allow read: if isStaff(); allow write: if false;`
   - `settings/policy/history/{versionId}`: `allow read: if isOffice(); allow write: if false;`
4. **Live Behaviour Wiring (W0-2 Exit Criterion — *"A setting changes behaviour without a release"*):**
   - `resolveBufferMinutes(constraints, policy)` in `packages/shared/src/domain/scheduling.ts` accepts `policy` (`defaultVehicleBufferMinutes`, `defaultTransitBufferMinutes`) and is wired live into:
     - Admin **Dispatch Board** (`DispatchBoard.tsx`) and **Booking Detail Panel** (`BookingDetailPanel.tsx`) via `checkCleanerSchedulingConflicts`.
     - Cloud Functions `listOpenShifts` (`functions/src/callable/shifts.ts`, `functions/src/lib/openShifts.ts`) and `claimJob` (`functions/src/jobs.ts`).
   - `defaultOdspMonthlyLimit` and `defaultVehicleBufferMinutes` are wired into `RegisterStaffModal.tsx` (`StaffTable.tsx`).
   - `earningsCautionThreshold` is wired live into the FSM Staff Profile Safe-to-Earn gauge (`apps/fsm/src/pages/ProfilePage.tsx`).
5. **Admin UI (`apps/customer/src/components/admin/SettingsTab.tsx`, `usePolicySettings.ts`, `AdminPage.tsx`, `adminTabs.ts`):**
   - Added **Settings & Policies** (`Paramètres et politiques`) tab with all 4 policy sections, change-reason input, Owner save/reset bar, Manager read-only banner, and chronological **Policy Version History**.
   - Full EN/FR translations in `apps/customer/src/i18n/locales/en.json` and `fr.json`.
