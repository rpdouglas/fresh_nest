## Form → Firestore Mapping

All `BookingFormData` fields map cleanly to the `bookings` schema. Eight fields are derived at submit time:

| Firestore field | Source |
| :--- | :--- |
| `language` | `i18n.language === 'fr' ? 'fr' : 'en'` |
| `leadSource` | `detectLeadSource(searchParams)` — URL params `?ref=` / `?utm_source=`; fallback `'organic'` |
| `status` | Always `'pending'` |
| `assignedTo` | Always `null` |
| `isAirbnb` | `serviceType === 'airbnb'` |
| `photoConfirmation` | `serviceType === 'airbnb' \|\| serviceType === 'commercial'` |
| `fsmAppointmentId` | `null` (Phase 6) |
| `createdAt` | `serverTimestamp()` |

`marketingConsent` (boolean) from the form is destructured out and never written directly. CASL mapping:
- When `true`: writes `marketingConsent: true`, `consentTimestamp: Timestamp.now()`, `consentMethod: 'booking-form-v2'`
- When `false`: all three fields omitted entirely (not `null`) per COMPLIANCE.md

---

## Schema Update

Added three CASL fields to `docs/firestore-schema.md`:
- `marketingConsent` (`boolean`, optional)
- `consentTimestamp` (`Timestamp`, optional — present only when consent given)
- `consentMethod` (`string`, optional — `'booking-form-v2'`)

These were required by `COMPLIANCE.md` but absent from the schema before E16.
