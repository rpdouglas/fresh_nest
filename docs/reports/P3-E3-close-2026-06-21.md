## Known Limitations & Follow-Up Work

1. **`onBookingCreated` fires immediately on admin creation** — sends confirmation email/SMS to the client even for `status: 'pending'`. For deferred notifications (e.g. "enter now, confirm later"), the P3-E26 Quote-First Booking flow is the planned solution.

2. **No duplicate email check** — admin can create a second booking for the same email/date. A future duplicate-detection check could be added when P3-E26 scopes the booking state machine.

3. **lint pre-existing failures** — the e2e and test files have unrelated type errors that cause `npm run lint` to exit non-zero. These should be addressed in a dedicated P3-E8 / clean-up epic.

4. **`firestore.rules` requires manual deploy** — `firebase deploy --only firestore:rules` must be run by a human after review. The rule file has been updated and is ready.
