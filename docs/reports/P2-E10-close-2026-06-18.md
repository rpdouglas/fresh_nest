## 1. Why Strategy 1 Was Chosen

Strategy 1 delivers rigorous security rules verification via the official `@firebase/rules-unit-testing` Firestore emulator while keeping Playwright E2E execution lightweight. By injecting Auth, Stripe, and Storage mocks in the browser window context (`page.addInitScript`) and intercepting Firebase REST endpoints with `page.route()`, the full E2E suite runs in CI without the Auth or Storage emulators. This keeps PR feedback fast (< 10 seconds for Vitest, < 3 minutes for Playwright on Chromium) while still exercising the real Firestore security rules compiler.

Strategy 2 (full emulator hybrid) was rejected due to complex synchronisation overhead and CI brittleness. Strategy 3 (mock-only rules) was rejected because it leaves `firestore.rules` entirely untested — a direct compliance risk for P12 Sarah.

## 6. Deviations from Approved Plan

### AdminBookingModal E2E test not written
The plan lists `apps/customer/e2e/fsm.spec.ts` as covering FSM login, job checklist, and photo upload. It separately calls out admin booking creation via `AdminBookingModal` as an acceptance criterion. No `AdminBookingModal` E2E test was added in this epic.

**Reason:** P1-E6 (Admin Booking Creation) is listed as ⬜ Not Started in `ACTIVE_CYCLE.md`. The `AdminBookingModal` component does not yet exist in the codebase. Writing a Playwright test for a component that has not been built would produce a test that can only fail. The test scaffold will be added as part of P1-E6 execution.

### `analytics.ts` unit tests in `src/lib/firebase/`, not a new file
The master plan's task list says "Add unit tests for `analytics.ts`". The test file was found to already exist at `apps/customer/src/lib/firebase/analytics.test.ts`. It was counted as complete without modification.

### FSM job flow tests use Firebase REST API mocking, not a full authenticated session
Strategy 1 states mocks are "injected in the browser window context via Playwright scripts." For the FSM job flow, Firebase Auth REST endpoints (`identitytoolkit.googleapis.com`, `securetoken.googleapis.com`) and Firestore REST endpoints are intercepted via `page.route()`. A `makeMockJwt()` helper constructs a valid-structure (unsigned) JWT with `role: 'staff'` claims, which the Firebase Web SDK v9 accepts on the client side without signature verification. This achieves the Strategy 1 intent without the Auth emulator.
