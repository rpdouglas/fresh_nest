# P3-E27-A1 Close Report — Fix Terms Pre-Acceptance Compliance Bug
**Date:** 2026-06-21
**Epic:** P3-E27-A1 (sub-phase of P3-E27 Employee Onboarding System)
**Priority:** P0 — PIPEDA compliance violation
**Strategy executed:** Strategy 1 (null-out + auditLog migration CF)

---

## Summary

Closed a live PIPEDA compliance violation where `useStaff.registerStaff()` wrote
`compliance.acceptedTermsVersion: '1.0'` and a fake `termsHistory` entry at admin registration
time — before any employee had seen or agreed to anything. The fabricated consent record carried
an admin-controlled timestamp, not the employee's own consent timestamp.

## PIPEDA Posture After This Fix

| Before | After |
|---|---|
| Admin registration created a false `acceptedTermsVersion: '1.0'` record with admin timestamp | Registration writes `null` — no consent claimed |
| `termsHistory` contained an entry with `acceptedAt: adminRegistrationTime` | `termsHistory: []` — empty until employee provides real consent |
| TermsConsentOverlay could be silently skipped if `CURRENT_TERMS_VERSION === '1.0'` | Overlay always shows when `acceptedTermsVersion === null` |
| Real employee IP and timestamp: never captured on first registration | Captured by TermsConsentOverlay on first FSM login |
