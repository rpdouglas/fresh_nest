## Architecture Notes

### `aria-live` strategy in StepIndicator
The visible `<p>` containing the progress text ("Step 2 of 4") now carries `aria-live="polite" aria-atomic="true"`. When `currentStep` changes, React re-renders the paragraph content, triggering the live region announcement. Screen readers announce the new text without requiring the user to navigate back to the indicator. The step dot group has `role="group"` with the same `aria-label` for users who tab through the dots directly.

### Admin `text-xs` → `text-sm` (not `text-base`)
In compact card/badge contexts (DispatchBoard shift metadata, AuditLogsTable diff values, PayRatesManager rate badges), `text-xs` (12px) was uplifted to `text-sm` (14px) rather than `text-base`. These elements appear in fixed-width table columns or compact card rows where `text-base` would break the layout. The step is an improvement from 12px → 14px; a full layout redesign to support 16px in these contexts is Phase 4 scope.

### axe audit excludes iframes
`@axe-core/playwright` is configured with `.exclude('iframe')` to prevent Stripe's payment iframe (Step 4) from generating third-party axe violations outside our control.

### Admin auth in axe test
The `/admin` axe test navigates to the route and audits whatever the unauthenticated view renders (typically the login page redirect). This is intentional — auditing the full authenticated admin portal requires session mocking that is out of scope for a WCAG audit spec.
