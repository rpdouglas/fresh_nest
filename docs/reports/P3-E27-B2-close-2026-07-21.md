## Work Done

1. **Schema Migration**:
   - Added `backgroundCheck: { consentGiven, consentGivenAt, consentIpAddress, status, completedAt, provider?, notes? }` to the `Staff` type in `packages/shared/src/types/staff.ts`, replacing the fabricated `onboardingChecklist.backgroundCheck: boolean` flag that was written by the admin at registration before the employee had ever consented to anything.
   - Updated `staffConverter` in `packages/shared/src/firebase/converters.ts` to parse `backgroundCheck` timestamps and default legacy docs (pre-migration staff records that only had the old boolean) to `{ consentGiven: false, status: 'not_started', ... }` so the UI never crashes on old data.
   - Updated `docs/firestore-schema.md` to document the new field.

2. **Cloud Functions**:
   - `onStaffRegistered` now initializes the structured `backgroundCheck` object instead of the boolean flag.
   - New callable `submitBackgroundCheckConsent`: employee-only, scoped to `request.auth.uid` (never client-supplied), idempotent, writes a server-observed `consentGivenAt` timestamp and `consentIpAddress` (from `request.rawRequest.ip`).
   - New callable `updateBackgroundCheckStatus`: admin-only (same authorization pattern as `resendWelcomeEmail`), validates the status enum, writes `status`/`completedAt`/`provider`/`notes`, and logs every change to `auditLog`.
   - Both exported in `functions/src/index.ts`.

3. **`firestore.rules`**: documented that `backgroundCheck` is intentionally excluded from the `staff/{staffId}` self-service `hasOnly()` allowlist — it was already implicitly closed to direct client writes, so no new rule logic was needed. All writes go through the two callables (Admin SDK, bypasses rules).

4. **FSM Consent Screen**: new `BackgroundCheckConsentScreen.tsx`, modeled on `TermsConsentOverlay.tsx`'s UI shell, mounted in `FsmLayout.tsx` ahead of `TermsConsentOverlay` (`z-[60]` vs `z-50`, so background check is always resolved first, matching the eventual P3-E27-C1 screen order). Includes an "I do not consent" path that signs the employee out.

5. **Admin UI**: `StaffTable.tsx` gained a Background Check column (status badge + inline status/provider editor calling `updateBackgroundCheckStatus`), and `useStaff.ts` gained the corresponding hook method.

6. **Dispatch Guard**: `checkCleanerSchedulingConflicts` (`scheduling.ts`) and `DispatchBoard.tsx`'s proactive conflict badges now treat `backgroundCheck.status !== 'cleared'` as a warning requiring admin override, reusing the existing earnings/travel/blocked-window override + `auditLog` mechanism — no new override plumbing needed.

7. **i18n**: `fsm.compliance.backgroundCheck.*` (10 keys, EN/FR) and `admin.override.backgroundCheckWarning` (EN/FR) added with full translations.

8. **user-guide/admin-guide.md**: documented the new Background Check column and dispatch safeguard; also fixed a stale "P12 Sarah" reference (pre-v4 persona name) to "P12 Lauren" while in the file.
