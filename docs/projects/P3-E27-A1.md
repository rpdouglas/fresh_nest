# P3-E27-A1 — Fix Terms Pre-Acceptance Compliance Bug

**Epic parent:** P3-E27 Employee Onboarding System

**Priority:** P0
**Complexity:** S
**Created:** 2026-06-21

## Background

`useStaff.registerStaff()` in `apps/customer/src/components/admin/hooks/useStaff.ts` writes
`compliance.acceptedTermsVersion: '1.0'` and a `termsHistory` entry timestamped at the admin
registration moment — before the employee has seen or agreed to anything. This creates a false
PIPEDA consent record in Firestore: the timestamp belongs to the admin action, not to employee
consent. Approximately 10 existing production staff documents carry this false record.

Additionally, `TermsConsentOverlay.tsx` shows only when `acceptedTermsVersion !== CURRENT_TERMS_VERSION`.
A staff member registered with `acceptedTermsVersion: '1.0'` would be incorrectly skipped by the
overlay in any environment where `CURRENT_TERMS_VERSION === '1.0'`, producing a second compliance gap:
the overlay never fires and no real consent is ever collected.

## Scope (agreed in grill-me session 2026-06-21)

### Going-forward fix (new registrations)
1. `useStaff.registerStaff()` writes `compliance: { acceptedTermsVersion: null, termsHistory: [] }`
2. `TermsConsentOverlay` show condition includes `null` check:
   `staffProfile.compliance?.acceptedTermsVersion == null || acceptedTermsVersion !== CURRENT_TERMS_VERSION`
3. `packages/shared/src/types/staff.ts`: `acceptedTermsVersion: string` → `string | null`
4. `docs/firestore-schema.md` updated with the new type

### Existing records migration
5. One-shot callable Cloud Function `migrateComplianceRecords` (admin SDK):
   - Iterates all `staff` documents
   - If `compliance.acceptedTermsVersion !== null`, sets it to `null` and `compliance.termsHistory` to `[]`
   - Writes an `auditLog` entry for each document patched: `{ collection: 'staff', documentId, field: 'compliance', oldValue, newValue: null, changedBy: 'P3-E27-A1-migration', reason: 'PIPEDA false-consent remediation', overrideType: 'compliance_migration' }`
   - Admin-callable (requires `isAdmin()` auth check); to be triggered once from admin console then
     deleted/disabled in the next deploy
