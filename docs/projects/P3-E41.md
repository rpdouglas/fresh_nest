## Owner decision (2026-11-23)
**Option B approved:** one repo (`rpdouglas/fresh_nest`), one Firebase project (`freshnest-aa51e`), one sign-in. FNC Landing moves in as `apps/ops`; its payroll and invoicing logic is kept; Camelo stays the source for schedule and time until the FSM cutover gate, then is replaced report by report.
This **reverses FNC Landing decision 0046** ("stays a separate app", 2026-10-27). The reversal is recorded in ADR-022 here and must also be recorded in `blurb` (`docs/decisions/0047-…`) when that repo is frozen (step 1 below).

## Scope (Phase 1)
1. **Freeze `blurb`:** fixes only, no new features (owner rule from approval). Record decision 0047 there; park `lead-tracking-spec.md` permanently (P3-E40 is the one pipeline).
2. **Code in:** `blurb/web` → `apps/ops`; `blurb/functions` → server code for the ops API in this repo; `blurb/e2e` (pretend Camelo) → ops browser tests. Git history preserved where practical (`git subtree` or a documented import commit).
3. **Hosting:** new Hosting target `freshnest-ops` (site `freshnest-ops`), custom domain `ops.freshnestco.ca`; `/api/**` rewrites to the ops function in `freshnest-aa51e`.
4. **Secrets:** `CAMELO_TOKEN`, `SCHEDULE_STAFF` (and `SCHEDULE_EDITORS` if kept) set in `freshnest-aa51e` Secret Manager by the human. **Use the same `CAMELO_TOKEN` value**: cleaner-session and stored-token keys are derived from it (HKDF in `who.ts`, `routes/clock.ts`), so copied records stay readable.
5. **Data:** copy the `schedule*` collections (`scheduleChangeLog`, `scheduleCleanerTokens`, `scheduleClientRates`, `scheduleFeedback`, `scheduleInvoiced`, `scheduleLiveHandled`, `schedulePlaces`, `scheduleSettings`, `scheduleSnapshots`, `scheduleSoloOk`, `scheduleVisitPhotos`) from `lilypad-strategy-design` `(default)` into `freshnest-aa51e` `(default)` (and a test copy into `freshnest-dev`); copy the photo bucket `lilypad-strategy-design-schedule-photos` to a new private bucket in `freshnest-aa51e` with the same 1-year lifecycle rule. Count-checked script, dry run first, human runs `--apply`.
6. **Office identity:** office users of the ops app are the Owner / Manager accounts (`admins` + custom claims, ADR-017) — per the approved strategy.
7. **Cleaner identity:** cleaners keep Camelo's 6-digit code sign-in into My week for this phase (moves to `apps/fsm` in phase 2). They sign in once on the new address (sessions are kept per web address).
8. **Protection:** `schedule*` collections denied to all clients in `firestore.rules` (server-only, as today); added to backups (W0-5 covers `(default)`) and documented in `firestore-schema.md`; admin portal and ops hub link to each other.
9. **Parallel run:** both sites live for one full pay period, Camelo writes (approve, edit) made in **one** site only — the new one — after the switch day. Old site read-only after the switch, then switched off at the gate.
10. **Docs:** `firestore-schema.md`, `COMPLIANCE.md` (ops data, photos, retention), `user-guide/admin-guide.md` (ops hub), `user-guide/staff-guide.md` (new address for My week), `HANDOFF.md`, runbook `docs/runbooks/ops-migration.md`.

## Out of scope (later phases)
Client/site records, moving prices onto client records, moving My week/clock-in into `apps/fsm`, French for office screens, replacing Camelo reads, merging the ops hub and admin portal into one app.

## Acceptance criteria / persona tests
1. **P12 Lauren:** signs in to `ops.freshnestco.ca` with her Owner account; every hub (Home, Schedule, Hours & pay, Billing, Clients) loads real Camelo data.
2. **P16 Ryan:** signs in with his Manager account and sees the same reports; a non-office account gets 403 on every office route.
3. **Pay gate:** for one full pay period, Payroll hours per cleaner and Invoicing totals per client on the new site equal the old site to the cent (written comparison in the close report).
4. **Data gate:** every copied collection and the photo bucket match source counts; prices, invoice ticks and feedback show identically for 3 sample clients.
5. **Cleaner:** a cleaner signs in on the new address with the Camelo code, clocks in with a door photo, adds a before/after photo; the office sees it.
6. **Safety:** `/api/health` returns 200 with the deployed build; every other route returns 401 without sign-in; rules tests prove `schedule*` is unreadable from clients.
7. **Build:** `npm run build && npm run lint` at the root, ops unit tests and ops browser tests (pretend Camelo) pass in this repo's CI.
