## Scope (Phase 1)
1. **Freeze `blurb`:** fixes only, no new features (owner rule from approval). Record decision 0047 there; park `lead-tracking-spec.md` permanently (P3-E40 is the one pipeline).
2. **Code in:** clean snapshot import pinned to `blurb`'s `live` tag SHA: `blurb/web` → `apps/ops`; `blurb/functions` → `functions-ops`; `blurb/e2e` (pretend Camelo) → `apps/ops/e2e`; `blurb/docs/decisions` → `docs/decisions/fnc` (read-only history). Both `apps/ops` and `functions-ops` remain isolated outside root npm workspace hoisting (own lockfiles) so Tailwind v4 / TS pins cannot leak into `apps/customer` or `apps/fsm`.
3. **Hosting & CI:** new Hosting target `freshnest-ops` (site `freshnest-ops`), custom domain `ops.freshnestco.ca`; `/api/**` rewrites to `scheduleApi` (`codebase: "ops"`) in `freshnest-aa51e`. Existing `firebase-deploy.yml` functions job scoped strictly to `--only functions:default`; Phase 1 deploys `functions:ops` + `hosting:freshnest-ops` in lockstep via manual `workflow_dispatch` (`deploy-ops.yml`) with an automated `/api/health` smoke check.
4. **Secrets:** `CAMELO_TOKEN`, `SCHEDULE_STAFF` set in `freshnest-aa51e` Secret Manager by the human (`SCHEDULE_EDITORS` retired under Strategy 2). **Use the same `CAMELO_TOKEN` value**: cleaner-session and stored-token keys are derived from it (HKDF in `who.ts`, `routes/clock.ts`), so copied records stay readable.
5. **Data:** copy the `schedule*` collections (`scheduleChangeLog`, `scheduleCleanerTokens`, `scheduleClientRates`, `scheduleFeedback`, `scheduleInvoiced`, `scheduleLiveHandled`, `schedulePlaces`, `scheduleSettings`, `scheduleSnapshots`, `scheduleSoloOk`, `scheduleVisitPhotos`) from `lilypad-strategy-design` `(default)` into `freshnest-aa51e` `(default)` (and a test copy into `freshnest-dev`); copy the photo bucket `lilypad-strategy-design-schedule-photos` to a new private bucket in `freshnest-aa51e` with the same 1-year lifecycle rule. Count-checked script, dry run first, human runs `--apply` immediately after putting `fnc-reports.web.app` into full read-only mode.
6. **Office identity (Strategy 2):** office users sign in to `ops.freshnestco.ca` via `freshnest-aa51e` Firebase Auth Google Sign-In (matching `useAdminAuth` + `syncMyRole`). `functions-ops/src/who.ts` verifies the Firebase ID token AND checks `admins/{email}` (`owner` or `manager`) so newly pre-approved Managers work immediately and revoked accounts lose payroll access immediately.
7. **Cleaner identity:** cleaners keep Camelo's 6-digit code sign-in into My week for this phase (moves to `apps/fsm` in phase 2). They sign in once on the new address (sessions are kept per web address).
8. **Protection:** `schedule*` collections denied to all clients in `firestore.rules` (server-only, as today); added to backups (W0-5 covers `(default)`) and documented in `firestore-schema.md` §17; admin portal and ops hub link to each other.
9. **Parallel run & sunset:** switch on the first Friday after staging/`freshnest-dev` verification passes. Put `fnc-reports.web.app` into **full read-only mode** (Camelo AND Firestore writes disabled + banner pointing to `ops.freshnestco.ca`) right before the final `--apply` copy so zero split-brain writes occur. Run an automated payroll & invoicing parity comparison script at pay-period end. At the gate, shut down `blurb`'s `scheduleApi` immediately and serve a lightweight service-worker-unregistering redirect page on `fnc-reports.web.app` → `ops.freshnestco.ca` for 8 weeks, then disable and archive `blurb`.
10. **Docs:** `firestore-schema.md` §17, `COMPLIANCE.md` (ops data, photos, retention), `user-guide/admin-guide.md` (ops hub), `user-guide/staff-guide.md` (new address for My week), `HANDOFF.md`, runbook `docs/runbooks/ops-migration.md`.

## Resolved decisions (owner sign-off 2026-11-23)
- **Strategy:** **Strategy 2** — lift & shift + unified Fresh Nest office auth (`owner`/`manager` via Firebase Auth + live `admins/{email}` check); payroll, invoicing and Camelo code untouched.
- **Q1 Tailwind v4 in `apps/ops`:** **Keep for Phase 1** as a scoped exception (ADR-022) and isolate `apps/ops` + `functions-ops` outside root npm workspace hoisting (explicit `workspaces: ["apps/customer", "apps/fsm", "packages/*"]`, own lockfiles).
- **Q2 Collection names:** **Keep `schedule*`** for Phase 1 (documented in `firestore-schema.md` §17; zero payroll-code churn).
- **Q3 Switch day & cutover:** **First Friday after staging/`freshnest-dev` verification passes.** Old `fnc-reports.web.app` goes into **full read-only mode** (Camelo + Firestore writes off + redirect banner) right before the final `--apply` copy, verified at pay-period end by an automated payroll & invoicing parity diff script.
- **Q4 Deploys:** PRs run ops unit tests, E2E (pretend Camelo), and preview channel. Production scopes existing `firebase-deploy.yml` job to `--only functions:default` and deploys `functions:ops` + `hosting:freshnest-ops` together in lockstep via manual `workflow_dispatch` (`deploy-ops.yml`) with a `/api/health` smoke check during Phase 1, moving to auto-deploy after the pay gate.
- **Q5 Old address:** At the pay gate, shut down `blurb`'s `scheduleApi` immediately and serve a lightweight service-worker-unregistering redirect page on `fnc-reports.web.app` → `ops.freshnestco.ca` for **8 weeks**, then switch off and archive `rpdouglas/blurb`.
- **Import method:** Clean snapshot import pinned to `blurb`'s `live` tag SHA (`blurb` remains archived on GitHub for full history).
- **Q6 Contractors** (from P3-E40): "all staff are employees" vs contractor lead owners — out of scope for P3-E41, tracked separately.
