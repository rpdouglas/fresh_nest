# P3-E34 — Task Lists on Scheduled Jobs (saved lists + on-the-fly lists)

**Type:** Feature (admin + FSM) · **Priority:** P1 · **Complexity:** M
**Opened:** 2026-10-27 · **Status:** ✅ Complete (2026-10-27) — [close report](../reports/P3-E34-close-2026-10-27.md)
**Plan:** [`plans/P3-E34_PLAN.md`](../plans/P3-E34_PLAN.md)

## Request (human, 2026-10-27)
> "We need the ability to create task lists and attach those task lists to scheduled jobs. We should be able to use pre-saved lists and create new lists on the fly."

## What exists today
- **Saved lists:** the admin **Checklist Templates** tab (`ChecklistTemplateManager.tsx`) already creates, edits and deletes saved lists in `checklistTemplates`.
  - Each list has `name`, `serviceType`, `active` and `tasks[]`.
  - Each task has an EN label, an FR label, an icon, "photo required" and a before/after phase.
- **Attaching a list to a job:** this is automatic only. `functions/src/jobs.ts` `resolveChecklistTemplate()` picks the first active template whose `serviceType` matches the booking, or else the first active template. It stores the **template ID** on `jobs.checklistTemplate`.
- **Cleaner app:** `apps/fsm/src/pages/JobPage.tsx` subscribes to that template **live** and records `checklistCompletions[]` by `taskId`.

## Gaps
1. **No choice of list:** an admin can't choose which saved list a job gets. It is always decided by service type.
2. **No one-off lists:** an admin can't build a list for one job (e.g. "Gallagher unit 4: restock coffee pods, photo of hot tub cover").
3. **Lists change under existing jobs:** a job points at a live template. Editing or deleting the template changes or empties the checklist of jobs that are already scheduled, in progress or completed. Completion proof then no longer matches what the cleaner saw. Despite `firestore-schema.md` saying "snapshotted at creation", nothing is copied.
4. **No choice for recurring work:** recurring bookings (renewals) can't keep a chosen list. Every renewal re-resolves by service type.
5. **Schema doc drift:** `firestore-schema.md` §8 describes tasks as `labelKey`. The code uses `labelEn` / `labelFr`. Fix the doc as part of this epic.

## In scope
1. **Choose a saved list per job:** from the Dispatch Board job card and the booking detail panel (Bookings tab).
2. **On-the-fly list:** start blank or from a saved list, add, remove or reorder tasks (EN + FR label, icon, photo required). Attach the result to the job. Optionally tick **"Save as a new saved list"**.
3. **Job snapshot:** when a list is attached, its tasks are **copied onto the job**, so later template edits don't change it.
4. **Recurring:** an optional per-booking list choice that renewals and their jobs inherit.
5. **Cleaner app:** reads the job's own tasks, and falls back to the template for older jobs.
6. **Guardrail:** the list can't be swapped once the job is `in_progress` or `completed`.

## Out of scope
- Customer-facing anything. Clients never see task lists, and there are no prices (P3-E29).
- Cleaners creating or editing lists. Admins only.
- Merging several saved lists into one job (Strategy 3 only).
- Machine translation of task labels. The admin types both EN and FR.

## Constraints
- EN/FR only. Every UI string goes through `t()`. Task labels are admin data in both languages, not i18n keys.
- Tailwind v3 tokens, `rounded`, 48px targets, phone layout via the P3-E33 `AdminDialog`.
- `firestore.rules` must not change. Admins can already update `jobs` and `bookings`, and cleaners' allowed job keys are unchanged.
- Schema additions are documented in `firestore-schema.md` in Phase C.

## Acceptance criteria / persona tests
- **P12 at 390×844:**
  - from a Dispatch Board job, choose **Change checklist → saved list "Airbnb Turnover"** in ≤ 4 taps;
  - or build a 3-task custom list and attach it.
  - The job shows the list name and task count.
- **Snapshot:** after the list is attached, editing or deleting the saved template leaves the job's tasks unchanged (unit + emulator test).
- **P11:** in the FSM app in FR, the job shows the custom tasks' FR labels and icons. A "photo required" task can't be completed without a photo.
- **Recurring (P1):** a booking with a chosen list produces a renewal whose job carries the same list.
- **Guardrail:** an `in_progress` job's checklist control is disabled, with a plain-language reason.
- **Back-compat:** existing jobs that only have a template ID still show their checklist in the FSM app.
- **Desktop:** the P3-E33 1280px screenshot guard still passes, except the intended new checklist control on the job and booking panels.
