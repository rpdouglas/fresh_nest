# P3-E27-A2 — Fix UID Linking Race Condition

**Epic parent:** P3-E27 Employee Onboarding System
**Sub-phase:** A — Emergency (ship immediately)
**Priority:** P0
**Complexity:** M
**Created:** 2026-06-22
**Depends on:** P3-E27-A1 ✅ (2026-06-21)

---

## Background

When a new staff member is registered, Lauren currently uses the admin UI which calls
`addDoc(collection(db, 'staff'), docData)` client-side, generating a random Firestore document ID.
The employee then logs into the FSM app — their Firebase Auth UID does not match the random doc ID.
`StaffAuthProvider.tsx` detects no doc at `staff/{uid}`, then runs an email-based migration:
queries `staff` by email, copies the doc to `staff/{uid}`, and deletes the old one — **all
client-side, inside an `onSnapshot` callback, using a plain `let isLinking = false` flag** that
is not atomic across re-renders or rapid auth state changes.

Every new hire hits this path. If two auth-state events fire before the `setDoc` write completes
(e.g., token refresh during the async operation), the migration can run twice — resulting in a
duplicate write or a deleted-then-missing profile. The employee sees `fsm.login.errorNoProfile`
and cannot log in.

---

## Agreed Design (grill-me session 2026-06-22)

### `onStaffRegistered` Cloud Function (new)
- Callable, admin-only
- Receives `RegisterStaffInput` payload
- Calls `admin.auth().createUser({ email, emailVerified: false })` — no password, passwordless flow
- Maps Firestore `role` to Auth custom claim: `cleaner/lead → 'staff'`, `supervisor → 'supervisor'`
- Calls `admin.auth().setCustomUserClaims(uid, { role: authClaim })`
- Writes `staff/{uid}` doc (UID as document ID) using Admin SDK — atomically
- Returns `{ uid, email }`

### `useStaff.registerStaff()` (changed)
- Body replaced with `httpsCallable(functions, 'onStaffRegistered')` call
- `RegisterStaffInput` type becomes the CF payload directly
- Returns on success; surfaces CF error via existing `submitError` state in `RegisterStaffModal`
- Pattern follows `useAdminAnalytics.ts` — `httpsCallable` from `firebase/functions` with `functions` from `@/lib/firebase/firebase`

### `StaffAuthProvider.tsx` (changed)
- Lines 82–108 (email-migration block) removed entirely
- `isLinking` variable removed
- Sentry warning added at the `else` branch entry: if `staff/{uid}` doesn't exist post-login,
  log to Sentry (`[P3-E27-A2] No staff doc at staff/{uid} — unexpected after A2 fix`) and
  sign the user out with `errorNoProfile`
- `setDoc`, `deleteDoc`, `getDocs`, `where`, `query` imports removed (no longer needed)

### `firestore.rules` (changed)
- Remove `allow create: if isAdmin()` from `match /staff/{staffId}`
- Admin SDK bypasses rules; client-side creates are now blocked as defence in depth
- `allow update` and `allow read` unchanged

### Tests (new)
- `apps/customer/src/components/admin/hooks/useStaff.test.ts` — unit test
  - Mocks `httpsCallable` and `functions`
  - Asserts `registerStaff(input)` calls the CF with the full `RegisterStaffInput` payload
  - Asserts `addDoc` is NOT called
