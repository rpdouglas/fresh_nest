# P3-E9 — Remove `window.__MOCK_*` from Production Code

## Objective
Remove the `window.__MOCK_SUBMIT__` escape hatch from `firestore.ts`. This guard runs on every real booking submission in production, creates a security surface, and conflates test concerns with production code. Replace with Playwright `page.route()` network interception in the E2E tests.

## Personas
All — every booking submission in production currently executes the mock guard.

## Key Tasks
1. Remove `if (typeof window !== 'undefined' && window.__MOCK_SUBMIT__) { ... }` block from `apps/customer/src/lib/firebase/firestore.ts`
2. Remove `__MOCK_SUBMIT__` type declaration from `apps/customer/src/vite-env.d.ts`
3. Update `apps/customer/e2e/booking.spec.ts` — replace `window.__MOCK_SUBMIT__ = ...` with `page.route()` intercepting the Firestore write REST endpoint
4. Update `apps/customer/e2e/checkout.spec.ts` — migrate only the Firestore-write portion to `page.route()`; leave `window.__MOCK_CREATE_PAYMENT_INTENT__` window-inject in place (deferred to P3-E1)

## Acceptance Criteria
- `firestore.ts` contains no `window.__MOCK_*` checks
- `apps/customer/src/vite-env.d.ts` has no `__MOCK_SUBMIT__` declaration
- `booking.spec.ts` uses `page.route()` for Firestore interception
- `checkout.spec.ts` uses `page.route()` for Firestore interception; Stripe portion unchanged
- `npm run build` passes with zero errors

## Schema Changes
None.

## Dependencies
None. (`window.__MOCK_CREATE_PAYMENT_INTENT__` cleanup deferred to P3-E1.)
