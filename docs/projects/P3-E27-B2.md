# P3-E27-B2 — Background Check Consent Collection

## Parent Epic
- **P3-E27**: Employee Onboarding System

## Objective
Collect explicit, timestamped, PIPEDA-compliant background check consent from the employee before any background check can be initiated, replacing the current fabricated `onboardingChecklist.backgroundCheck: boolean` flag (written by the admin at registration, before the employee has seen or agreed to anything) with a structured, legally defensible consent record the employee creates themselves.

## Personas
- **P12 Lauren Arsenault (Admin/Owner)**: legal gate — cannot knowingly let an uncleared employee onto a client job; needs visibility into consent/status and the ability to update it without a direct Firestore edit.
- **P8 Jasmine Beausoleil (Cleaner)**: must give informed, explicit consent before any background check is initiated on her — cannot be defaulted into one.
- **P11 Brenda Côté (Lead Cleaner, French-primary)**: must see and consent to this entirely in French.

## Key Tasks
1. **Schema migration**: replace `onboardingChecklist.backgroundCheck: boolean` with a structured `staff/{uid}.backgroundCheck` map (see Schema Changes). `onboardingChecklist` keeps `trainingCompleted` and other non-background-check keys.
2. **New FSM component** `BackgroundCheckConsentScreen` (`apps/fsm/src/components/auth/`), modeled on the existing `TermsConsentOverlay.tsx` UI shell (full-screen modal, bilingual, RTL-aware, brand tokens, 48px targets, IP/timestamp capture). Shown when the employee is logged in and `backgroundCheck.consentGiven` is not `true`. Includes an explicit consent checkbox and a "I do not consent" path that signs the employee out with instructions to contact Lauren — she cannot reach the FSM app without consenting.
3. **Gating order**: wire the new screen to appear *before* `TermsConsentOverlay` in the FSM app shell, matching the eventual 4-screen sequence P3-E27-C1 will formalize (background check consent is Screen 2 of that sequence; this epic ships it standalone since `OnboardingSequenceGuard` doesn't exist yet).
4. **`firestore.rules`** (security change — human approval required per CLAUDE.md): decide and implement how `backgroundCheck` writes are authorized — see the Phase A plan for the strategy choice; the current admin/self `hasOnly([...])` pattern used for `compliance` is not safely reusable as-is because `backgroundCheck` mixes employee-writable (consent) and admin-only (status/completedAt/provider/notes) fields in one map.
5. **Admin UI**: add a background-check status/provider/notes editor to `apps/customer/src/components/admin/StaffTable.tsx` (the full Staff Detail Panel is P3-E27-D1's scope; this only needs to unblock Lauren from editing status without the Firestore console).
6. **Dispatch board guard**: block assigning a job to a staff member whose `backgroundCheck.status !== 'cleared'` (`DispatchBoard.tsx` / scheduling utils), with a visible warning and an admin override that logs a reason to `auditLog`.
7. **Shared types/converters**: update `packages/shared/src/types/staff.ts` and `firebase/converters.ts`; update `onStaffRegistered` in `functions/src/callable/staff.ts` to initialize the new `backgroundCheck` object instead of the old boolean.
8. **i18n**: all new copy (consent text, checkbox, decline path, admin status labels) added to `en.json`/`fr.json` in both apps — zero hardcoded strings.

## Acceptance Criteria
- [ ] Background check consent screen is shown to a newly registered employee before they can reach the FSM app.
- [ ] Jasmine cannot proceed without explicitly checking the consent checkbox; declining signs her out with a message to contact Lauren.
- [ ] Consent is recorded with a server-observed timestamp and IP address (not client-supplied).
- [ ] An employee can never set their own `backgroundCheck.status`, `completedAt`, `provider`, or `notes` — enforced server-side.
- [ ] Lauren can view and update `backgroundCheck.status`/provider/notes from the admin Staff panel without a direct Firestore edit.
- [ ] Dispatch board shows a visual warning and requires an override reason (logged to `auditLog`) before assigning an uncleared employee to a job.
- [ ] Brenda sees the consent screen entirely in French (Linguistic_Auditor).
- [ ] Code builds cleanly and lint checks pass with zero errors.

## Schema Changes
### `staff` Collection
- `backgroundCheck`: `{ consentGiven: boolean, consentGivenAt: Timestamp | null, consentIpAddress: string | null, status: 'not_started' | 'pending' | 'cleared' | 'flagged', completedAt: Timestamp | null, provider?: string, notes?: string }` — **replaces** `onboardingChecklist.backgroundCheck: boolean`.
