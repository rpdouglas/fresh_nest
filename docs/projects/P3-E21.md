# P3-E21 — Firestore `withConverter()` Adoption

## Objective
Adopt typed Firestore converters (`withConverter()`) across the entire client-side applications (`apps/customer` and `apps/fsm`). This replaces over 20 instances of manual `Timestamp` casting patterns, enforces strict type safety for reads and writes, and prevents runtime type drift.

## Personas
- **P3 Margaret** — Accessible design and user reliability. Centralized parsing ensures dates are displayed correctly across client UIs without silent runtime failures.
- **P12 Lauren** — Admin operations. Operations dashboards, export views, and bookings queries compile with high type assurance.
- **P8 Jasmine / P11 Brenda** — Cleaner shift schedules, check-in history, and compliance acceptance timelines are retrieved accurately with correct timezone/object formats.

## Key Tasks
1. **Move `Review` Type to `@freshnest/shared`**:
   - Relocate the `Review` interface from `apps/customer/src/types/index.ts` to `packages/shared/src/types/common.ts` or similar, making it a canonical entity type.
2. **Create `firebase/converters.ts` in Shared Package**:
   - Create `packages/shared/src/firebase/converters.ts`.
   - Implement `FirestoreDataConverter` for all 7 Firestore collections.
   - Implement `cleanUndefined` to automatically strip `undefined` fields from payloads during writes.
   - Implement recursive `toDate` conversion for timestamps on reads.
   - Export collection helpers (e.g. `bookingsCollection(db)`) for clean developer usage.
3. **Refactor Helper & Library Files (`lib/firebase/`)**:
   - Update `apps/customer/src/lib/firebase/firestore.ts` to use the new typed collections and remove manual `Timestamp` casts.
4. **Refactor Hooks & Components**:
   - Update hooks (`useBookings`, `useStaff`, `usePayRates`, `useChecklistTemplates`, `useAuditLogs`, `useShifts`, `useMyAssignedShifts`, etc.) to use the helper collection factories.
   - Remove manual date casting statements in React files.
5. **Verify Project Compilation**:
   - Ensure the root builds cleanly via `npm run build`.
   - Run tests (`npm run test:customer` and `npm run test:fsm`) to verify no regressions in hooks/mock databases.

## Firestore Collection Configuration
The converters will be linked to the following schemas:

| Collection | Model Type | Key Date/Timestamp Fields Mapped | Helper Factory |
|---|---|---|---|
| `bookings` | `Booking` | `createdAt` | `bookingsCollection(db)` |
| `jobs` | `Job` | `createdAt`, `checkedInAt`, `completedAt`, `reviewRequestScheduledFor`, `photos[].uploadedAt`, `photos[].capturedAt`, `checklistCompletions[].completedAt` | `jobsCollection(db)` |
| `staff` | `Staff` | `createdAt`, `compliance.termsHistory[].acceptedAt` | `staffCollection(db)` |
| `reviews` | `Review` | `createdAt` | `reviewsCollection(db)` |
| `payRates` | `PayRate` | `createdAt`, `effectiveFrom`, `effectiveTo` | `payRatesCollection(db)` |
| `checklistTemplates` | `ChecklistTemplate` | None | `checklistTemplatesCollection(db)` |
| `auditLog` | `AuditEntry` | `changedAt` | `auditLogCollection(db)` |
