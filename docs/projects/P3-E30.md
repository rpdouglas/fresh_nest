## Problem

No app email is being delivered. Found 2026-10-01 after a test quote request on production:
the SMS arrived, the email did not. `onBookingCreated` logs show Resend rejecting the key:

```
client email failed: Client confirmation failed: API key is invalid
owner email failed:  Owner notification failed: API key is invalid
```

This affects every email the Cloud Functions send: client confirmations, owner
"New quote request" alerts, review requests and staff welcome emails. SMS (Twilio) works.

Separately, the business has no real inboxes on its own domain. `freshnestco.ca` DNS
as checked on 2026-10-01 (public DNS, nameservers `dns1/dns2.canspace.ca`):

| Record | Current value | Consequence |
|---|---|---|
| MX | `0 freshnestco.ca.` (points at itself) | Mail to `hello@freshnestco.ca` does not reach an inbox |
| TXT (root) | `hosting-site=lilypad-freshnest` only | No SPF |
| `_dmarc` | none | No DMARC |
| `resend._domainkey`, `send.` | none | Domain is not verified in Resend |

## Decisions (human, 2026-10-01)

1. **Zoho Mail for inboxes, Resend for the app's automated email** (option A). Both live on
   `freshnestco.ca`; no change of sending library. Rejected: Zoho ZeptoMail (code change, not free)
   and Zoho SMTP from the functions (needs a paid plan, send limits).
2. **DNS is managed at CanSpace** (canspace.ca). All records below are added there.
3. **Public contact email is `hello@freshnestco.ca`.** Already applied in PR #26 (commit `3d18587`).
4. **Quote requests are handled by Lauren + one office person**, from a shared `hello@` mailbox.
5. **"New quote request" alerts go to the shared inbox**, addressed to the `quotes@` alias so they can be filtered.
6. **Hiring/staff email is a separate `hr@` mailbox**, to keep applicants' personal information
   out of the shared customer inbox (PIPEDA).
7. **2 people need their own login today.**

## Mailbox plan (Zoho — 5 users max)

| # | Mailbox (Zoho user) | Who uses it | Aliases delivering into it |
|---|---|---|---|
| 1 | `lauren@` | Lauren | `admin@`, `accounts@`, `dmarc@` |
| 2 | `{office-person}@` | Office person | — |
| 3 | `hello@` (shared, access delegated to both) | Lauren + office person | `quotes@`, `bookings@`, `info@` |
| 4 | `hr@` | Lauren (+ whoever handles hiring) | `careers@` |
| 5 | *(spare)* | Future hire | — |

- `hello@` is a real mailbox, not a forwarding group: replies go out *from* hello@ and the
  whole customer conversation stays in one place.
- `noreply@` needs no Zoho mailbox. Only Resend sends from it.

## Setup steps (in order)

Steps 1–4 are done by the human in the Zoho, Resend and CanSpace dashboards. After each DNS
step the agent can verify the records from the codespace (see "Verifying DNS").

- [ ] **1. Zoho Mail**
  - [ ] Sign up and add `freshnestco.ca`. Choose the **Canadian data centre** if offered (PIPEDA, Quebec Law 25).
  - [ ] Add Zoho's verification TXT record at CanSpace.
  - [ ] Add Zoho's MX records (exact hosts Zoho shows) and **delete** the existing `MX 0 freshnestco.ca`.
  - [ ] Add Zoho's SPF TXT record at the root (`v=spf1 include:… ~all`).
  - [ ] Add Zoho's DKIM TXT record (`zmail._domainkey`).
  - [ ] Create the 4 users and the aliases in the table above; delegate `hello@` to both people.
- [ ] **2. Resend**
  - [ ] Add `freshnestco.ca` under Domains and enter the records Resend shows: a DKIM TXT
        (`resend._domainkey`) and MX + SPF on the **`send.`** subdomain. These do not clash with Zoho's root records.
  - [ ] Wait for the domain to show "Verified".
  - [ ] Create a new API key.
- [ ] **3. DMARC** — add TXT `_dmarc` = `v=DMARC1; p=none; rua=mailto:dmarc@freshnestco.ca`.
- [ ] **4. Secrets** (run before step 5; functions only read new secrets on redeploy)
  ```
  printf '%s' 'PASTE_THE_NEW_RE_KEY' | npx -y firebase-tools@latest functions:secrets:set RESEND_API_KEY --data-file=- --project freshnest-aa51e
  printf '%s' 'quotes@freshnestco.ca' | npx -y firebase-tools@latest functions:secrets:set OWNER_EMAIL --data-file=- --project freshnest-aa51e
  ```
- [ ] **5. Code changes in a follow-up PR, then merge it** (merging redeploys the functions with the new secrets).
      If no code changes are approved, redeploy the functions another way so they pick up the secrets.
- [ ] **6. End-to-end test** — see acceptance criteria.

### Verifying DNS

`dig` is not installed in the codespace; use DNS over HTTPS:

```
for t in MX TXT; do curl -s "https://dns.google/resolve?name=freshnestco.ca&type=$t"; echo; done
for n in _dmarc zmail._domainkey resend._domainkey send; do curl -s "https://dns.google/resolve?name=$n.freshnestco.ca&type=TXT"; echo; done
curl -s "https://dns.google/resolve?name=send.freshnestco.ca&type=MX"
```
