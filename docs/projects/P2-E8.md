# Project Spec: P2-E8 Firebase Custom Claims RBAC

## Objective
Migrate from the Firestore collection email allowlist pattern to cryptographically secure Firebase Custom Claims for Role-Based Access Control (RBAC).

## Background
Using a Firestore collection read in database security rules generates significant document reads. Attaching roles directly to auth tokens eliminates this overhead and allows supervisor/staff role structures.

## Personas Served
- **Admin/Staff Operations:** Requires secure multi-tenant permissions.
- **Security & Compliance:** Needs robust, tamper-proof roles.

## Key Tasks
- Define the role taxonomy: `admin`, `supervisor`, `staff`, `customer`.
- Create a Firebase Auth trigger Cloud Function `onUserCreated`:
  - Automatically sets `{ role: 'customer' }` in custom claims for new signups.
- Create an admin-only callable Cloud Function `setUserRole`:
  - Sets `{ role: 'admin' | 'supervisor' | 'staff' }` using `auth.setCustomUserClaims()`.
- Refactor `firestore.rules` security gates:
  - Replace `exists(/admins/)` with `request.auth.token.role == 'admin'`.
  - Add staff security rules: `request.auth.token.role == 'staff'`.
- Secure client routing in `apps/customer/src/App.tsx` and `apps/fsm/src/App.tsx` using `role` claims checks.

## Acceptance Criteria
- Firestore security rules evaluate without calling `exists()` lookups for roles.
- Admins can change user roles, and changes propagate on next token refresh.
- Unauthenticated users and customer users are blocked from admin and staff endpoints.
