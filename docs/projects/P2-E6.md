# Project Spec: P2-E6 Admin Pagination & Server-Side Analytics

## Objective
Convert all unbounded Firestore collections subscriptions into paginated queries, and migrate dashboard KPIs to a server-side cached Cloud Function.

## Background
Subscribing directly to entire collections (like `bookings` and `jobs`) without limits causes performance and cost issues as database volume grows. Admin dashboard hooks should leverage pagination and TanStack Query.

## Personas Served
- **Admin Operations (Lauren):** Needs high-speed data rendering and search capabilities.
- **Business Operations:** Requires fast and cost-effective database reads.

## Key Tasks
- Refactor `subscribeToBookings` to query in pages:
  - Default view to the last 90 days.
  - Implement cursor-based pagination with a limit of 50 documents.
  - Add date-range filters to `BookingsTable`.
- Write Cloud Function `getAnalyticsKPIs`:
  - Uses Firestore aggregation queries (`count()`, `sum()`) to compute analytics.
  - Caches output in `reports/analytics_cache` document with a 1-hour expiration TTL.
- Migrate admin API hooks to use TanStack Query `@tanstack-query-firebase/react` query models for local caching.

## Acceptance Criteria
- Admin Bookings panel fetches and renders no more than 50 booking entries initially.
- Analytics charts fetch data in under 2 seconds.
- Repeating navigation inside the admin dashboard shows cache hits and zero duplicate queries.
