# Project Spec: P2-E10 Test Coverage Expansion

## Objective
Raise unit test coverage to 60% lines/55% branches and write integration tests for Firestore security rules, client routing, and the checkout payment pipeline.

## Background
A payment-handling, PIPEDA-regulated platform requires test coverage to prevent security regressions, billing errors, and localization bugs.

## Personas Served
- **QA & Engineering:** Ensures high stability.
- **Customers & Admins:** Gain confidence that features function consistently.

## Key Tasks
- Set up and write Firestore Security Rules emulator tests under `apps/customer/test/firestore-rules.test.ts` using `@firebase/rules-unit-testing`:
  - Validate public booking creation limits (e.g., status must be `pending`, cannot set `assignedTo`).
  - Validate role boundaries (admins can write anything, staff can read/write their own shifts, customers can read/write their own bookings, others are denied).
- Raise Vitest thresholds in `apps/customer/vitest.config.ts`:
  - Set `lines` coverage threshold to 60%.
  - Set `branches` coverage threshold to 55%.
- Write Playwright E2E integration tests:
  - Simulate customer magic-link login and booking portal views.
  - Test Stripe checkouts using mock payment cards.
  - Test admin drag-and-drop dispatch and job creation.

## Acceptance Criteria
- Unit test coverage reaches $\ge 60\%$ lines and $\ge 55\%$ branches.
- All Firestore rules unit tests pass successfully.
- Playwright E2E suites verify magic-link login, Stripe checkout, and dispatch booking flows without failures.
