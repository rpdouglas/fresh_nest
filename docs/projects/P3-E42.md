**Type:** Admin operations / Camelo integration bridge · **Priority:** P1 · **Complexity:** M
**Opened:** 2026-11-25 · **Status:** ✅ Code complete (Strategy 2 approved & implemented 2026-11-25; awaiting PR merge & CI rules deploy)

**Relationships:** Connects **P3-E40 Sales Pipeline** (`apps/customer` Admin → Pipeline) to production **Camelo** (`https://api.camelohq.com/graphql`) as a Phase 1–2 bridge under **ADR-022 / P3-E41** until Camelo is retired in Phase 3.

## Problem
When Lauren (Owner) or Ryan (Manager) marks a lead **Won** in the Admin Portal Sales Pipeline (P3-E40), they must manually re-enter the client's name, email, phone, billing address, service address, lockbox/pet/property instructions, and intake notes into Camelo so cleaners can be scheduled and see the site instructions on **My week** (`apps/ops`). Re-typing creates duplicate clients, dropped lockbox/pet notes, and wasted office time.

Live production verification on `2026-11-25` confirmed Camelo's GraphQL API supports:
- `createClient` / `updateClient` / `destroyClient` (`name` required; `clientNumber`, `phoneNumber`, `email`, `billingAddress`)
- `createJobSite` / `updateJobSite` / `destroyJobSite` (`name`, `address`, `geoLat`, `geoLong`, `scheduleIds` required; `note`, `clientIds`, `color`, `wifiSsid`, `wifiBssid`)
- `createComment` / `updateComment` / `destroyComment` + `comments` with `CommentableTypeEnum = CLIENT` (alongside `TIMESHEET`, `SHIFT`, `TASK`, `DOCUMENT`)
- `schedules(first: 10)` returning workspace schedules (**Clients**, **Internal**, **On Call**)

## Resolved Design Decisions (`/grill-me`, 2026-11-25)

1. **Trigger & UX:** Review modal + one-click **"Send to Camelo"** button on Won leads in `LeadDetailPanel`, plus an automatic prompt when saving `stage = 'won'` on an unsynced lead.
2. **Duplicate / Returning Clients:** On modal open, auto-search Camelo `clients` by email, normalized phone, and name. Highlight matches so Lauren/Ryan can link the new Job Site to an existing Camelo Client or create a new Client. Persist Camelo IDs (`bookings/{id}.camelo`) to prevent duplicate pushes.
3. **Notes Mapping & Privacy (`COMPLIANCE.md` §2):**
   - **Job Site Note (`jobSite.note`, cleaner-visible on shifts & My week):** Pre-filled editable textarea from `booking.notes` + pets/Airbnb/home basics. **Strictly excludes** restricted e-agreement access codes in `agreements/{id}/private/access`.
   - **Client Comment (`createComment` with `commentableType: CLIENT`, office-visible):** Pre-filled editable textarea with service type, frequency, preferred date, language, internal quoted price (cents → formatted internal note), lead source, plus checkboxes to include selected P3-E40 `leadNotes` (contact log entries).
4. **Geocoding & Schedule Selection:** Geocode `booking.address` via OpenStreetMap Nominatim (address-only, no client name, reusing `schedulePlaces` cache per FNC decision 0009). If a rural address (e.g., Akwesasne / Cornwall Island / Snye QC) misses, show a clear warning letting Lauren/Ryan edit the address, enter manual `lat`/`lon`, or apply a one-click Cornwall-area fallback pin (`45.0213, -74.7303`). Default `scheduleIds` to Camelo's `"Clients"` schedule, changeable via dropdown.
5. **Post-Sync Actions & Pricing Scope:** Once synced, show a **"Synced to Camelo"** status panel on `LeadDetailPanel` with Client + Job Site details and inline controls to **add a follow-up Camelo Client note** or **update the Camelo Job Site note**. Keep Ops Hub pricing (`scheduleClientRates`) separate for Phase 2.
6. **Staging Safety & Fake Camelo:** Block live writes to production Camelo when `databaseId === 'freshnest-dev'` (show a clear dev/dry-run preview state instead). Extend `apps/ops/e2e/fake-camelo.ts` with client/job-site/schedule/client-comment support and run unit/emulator tests against pretend-Camelo mocks. Remove the temporary `scripts/probe-camelo-clients.mjs` script.

## Out of Scope

- Pulling restricted door/alarm codes from `agreements/{id}/private/access` (`COMPLIANCE.md` §2 prohibits exposing `private/access` outside Owner/Manager)
